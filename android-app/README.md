# Sahabat ODHIV Sumut — Android app source

This project wraps the existing Cloudflare dashboard:
https://sahabatodhivsumut.web.id/

## Version alignment — 16 October 2026

- Android package version: **1.2.27** (`versionCode 30`).
- Debug package: `1.2.27-debug`; expected artifact: `Sahabat-ODHIV-Sumut-APK-debug-v1.2.27`.
- Signed release package: `1.2.27`; expected artifact: `Sahabat-ODHIV-Sumut-APK-release-v1.2.27`.
- The online dashboard currently uses web version **1.1.48**. The APK loads the canonical HTTPS dashboard; online menu and backend changes become available when the website is deployed, while the native Android shell, permission behavior, camera/gallery handling, and offline fallback require a new APK build.
- Android and web use separate version sequences because they are independently packaged. Successful GitHub Actions artifacts are not the same as a published entry on the GitHub Releases page.

## What this build does

- Opens the existing dashboard over HTTPS; it does not copy Google Sheets data into the APK.
- Provides a privacy-safe local offline screen. Respondent data and synchronization remain online-only.
- Keeps dashboard login and backend APIs on the existing Cloudflare Worker.
- Allows image upload fields in the dashboard to open a chooser for either the device camera or an existing gallery photo. Video selection/capture is intentionally disabled.
- Uses a temporary cache file for camera photos and Android's system picker for gallery photos; it does not request broad access to all photos.
- Keeps in-dashboard notifications available while the dashboard is open.
- Includes a native Android notification channel, runtime notification permission request, vibration support, and a local notification test.
- Includes optional Android system biometric unlock (fingerprint/face where the device supports it, with device-credential fallback). This is a local app lock and does not replace dashboard server login.
- Opens the WebView directly without an artificial animated intro or delay, so users reach the dashboard promptly.
- Native remote push is not yet connected to Firebase Cloud Messaging (FCM). The existing Cloudflare Worker Web Push/VAPID service is a separate browser-push system; the APK must not claim to receive background remote push until an FCM project, Android app registration, and server credentials are configured and tested.
- Blocks cleartext HTTP, mixed content, file access from the remote page, third-party cookies, and navigation to non-dashboard sites inside the WebView.

## Build locally

Requirements: JDK 17, Android SDK Platform 35, Android Build Tools, and Gradle 8.9.

From this directory:
```sh
gradle assembleDebug
```

Installable debug APK:
`app/build/outputs/apk/debug/app-debug.apk`

The APK generated by GitHub Actions is a debug-signed test build, not a production or Play Store release. A production release needs a private signing key stored only in protected GitHub Actions secrets, a verified release workflow, versioning, and separate device/security testing. Do not upload the debug APK as the final public release.

## Build from GitHub

Open Actions → **Build Sahabat ODHIV Sumut Android APK** → Run workflow. Download the artifact named `Sahabat-ODHIV-Sumut-APK-debug` after the job succeeds. A push changing files under `android-app/` also triggers the workflow.

## Important test checklist

- Verify login/logout and session expiry on an Android device.
- Verify image upload can open the camera and gallery, upload a photo, and handle cancel/permission denial.
- Confirm video files are not offered by the image chooser.
- Verify respondent APIs remain protected when signed out.
- Verify notification permission and the local notification test.
- Verify biometric opt-in, success, cancel, fallback, and session expiry.
- Native remote push delivery is pending FCM project and server credential configuration; do not mark it complete until tested with the app closed.
- Verify offline screen appears with airplane mode enabled.

- Check the app in both portrait and landscape on a phone and an Android tablet; the activity is resizeable and the WebView uses the page's responsive viewport. Actual table wrapping and wide-screen layout still depend on the dashboard's web CSS.
- Verify Google Sheets and Drive synchronization only after reconnecting.
- Never test using exported real respondent data. Use synthetic data where possible.

## Current limitation

Background push notifications use the existing browser Web Push implementation. The APK currently implements local Android notifications and biometric unlock. Remote push delivery from the Workers to the native APK remains pending Firebase Cloud Messaging (FCM) setup: register package `id.sahabatodhiv.sumut`, provide the Firebase Android configuration, enable the FCM API, and configure a service account with permission to send messages. Do not commit service-account private keys to the repository. After configuration, build and test notification delivery with the app closed.

## Android device permissions

- Camera: the app launches Android's camera app only when a user selects the take-photo option. Android's camera app handles its own camera permission prompt. The app does not record video.
- Gallery: the system picker returns only the photo the user chooses; no broad media/storage permission is declared.
- Location: coarse/fine permissions are reserved for a future feature and should only be requested if a feature genuinely needs location. No background location is declared.
- Notifications: Android 13+ requires runtime notification permission for native app notifications.
- Calls/SMS: prefer opening the user's dialer or SMS app with an intent. The app does not request CALL_PHONE, SEND_SMS, READ_SMS, or call-log access.
- No microphone/audio capture, video capture, silent location collection, or background media collection is implemented.

Camera/gallery chooser behavior is implemented in the WebView upload flow, but it must still be tested on a physical Android device with the actual dashboard photo-upload fields.
